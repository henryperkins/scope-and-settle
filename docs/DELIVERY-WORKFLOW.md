# Approved work and delivery review

A designer explicitly starts work from an approved milestone. The service refreshes each approved work-start payment prerequisite, checks coherent unreversed payment and exact scope/revision, then stores one immutable delivery brief and operation. A delivery-acceptance balance does not fund its own work-start prerequisite.

The brief records approved deliverables/items, scope and request references, available evidence/node references, acceptance criteria, exact paid observations and the allowed Figma file and dedicated draft page. Standard Plugin API output creates editable draft scaffolds/checklist and preserves original nodes and selection. Repeated readback reuses the saved area; a missing/moved saved area requires review. The designer refines and reviews the draft. Specs, MCP generation, Code Layers and Code Connect remain disabled without verified target-file access; no verified repository mapping is attached for this engagement.

The plugin reads generated IDs and exports a PNG review snapshot. The backend validates the operation, file, bounded node graph, fixed page/area and PNG, and stores immutable hashes. Node readback and pixels retain client-supplied provenance; they do not establish independent native or provider verification.

After reviewing the exact snapshot and checklist, the designer explicitly submits it and receives a private client delivery link. This uses a distinct `delivery` grant for the exact review and review revision. Proposal/scope grants cannot accept delivery. Replacement output submitted for review invalidates older links and renewable grants. Requested changes, replacement and acceptance remain append-only events.

The client sees the saved image, criteria, proposal/review revisions, snapshot hash and agreed invoice consequence. Explicit same-origin consent records one acceptance transactionally before the recoverable balance invoice operation. Repeated or concurrent acceptance reuses that acceptance and invoice. Lost create responses search the stable invoice number; known provider IDs survive authority loss. Uncertain sends remain read-only and are not blindly replayed.

Delivery acceptance and payment stay independent. A deposit never announces whole-order Paid. A late deposit or balance refund preserves the accepted version and generated history while flagging financial review. Figma readiness events and generation completion do not accept work or create acceptance-triggered invoices.

The local implementation and verification are recorded in [through-T16 qualification](verification/agent-integrations-c-through-t16-2026-10-24.md). Real sandbox installment payments, native output/readback and independent designer review remain external gates.
