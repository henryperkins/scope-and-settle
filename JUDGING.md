# Scope & Settle: judging walkthrough

Use [judge entry](https://scope-and-settle.hperkins.com/judge), the private judging code, and the dedicated **personal sandbox buyer** supplied in the private testing instructions. No provider keys or local backend are needed for this hosted path. All content and payments are synthetic.

1. **Start your demo.** Enter the judging code and choose **Start a new demo**. Expect private designer access for a fresh run. Save it privately; it grants a role, not a verified identity. **Resume my demo on this browser** resumes only the run stored in that browser. Each click on Start deliberately creates a different run.
2. **Install the plugin.** Download the ZIP from judge entry and extract it. In **Figma desktop → Plugins → Development → Import plugin from manifest**, select the extracted `manifest.json`. Keep `code.js` and `ui.html` beside it. The ZIP's `SOURCE.json` records the source commit and file checksums; `/downloads/SHA256SUMS` provides the ZIP checksum.
3. **Open the designated file.** Follow the Figma link on judge entry and sign in to your own Figma account. The synthetic file permits editing by anyone with its link; no team invitation or paid seat is needed. Open this same file in Figma desktop. An arbitrary duplicate has a different file key and cannot supply this hosted demo's comments. Select the **Desktop checkout — synthetic demo** frame. Run **Scope & Settle** from Development.
4. **Connect and assess.** Copy designer access from judge entry, paste it into the plugin, and click **Connect**. Select the actual comment **“Can you add the mobile checkout?”**. Click **Attach selected frame**, then **Assess against the brief**. Expect a live model assessment citing the desktop-only agreement, a mobile deliverable, and a **$250** rate-card suggestion. The designer still reviews the terms. A clarification or provider error is shown honestly; no recorded answer is substituted.
5. **Create client review.** Review deliverables and the $250 total, then **Confirm terms & create client review link**. Open that separate client view. Expect the same proposal revision, brief revision, deliverables, and total. The client must check the consent box and choose **Approve change & prepare invoice**. Approval is explicit; it does not mean payment.
6. **Pay in sandbox.** Open the PayPal sandbox invoice and sign in with the dedicated personal buyer supplied privately. Complete the **$250 sandbox payment**. Do not use a real PayPal account or card. Return to the client page and choose **Refresh payment status**; expect **Paid**, based on PayPal invoice retrieval. In the plugin choose **Check payment**; expect **Paid** and **$0.00 due**, on the same revision. Close and reopen the plugin to confirm persistence.
7. **Start again.** Under designer **Demo controls**, choose **Reset my demo** and confirm. Expect a clean run with replacement access. This revokes the old run's designer and client access and clears its local evidence/orders. PayPal keeps sandbox invoices. Other judges' runs and the shared AI spending ledger remain intact.

## Recovery

- **Expired session:** ordinary sessions last at most 60 minutes. Browser and plugin renew automatically using their separately scoped resume credential. Access normally ends December 16, 2026 at 16:00 UTC. Revocation, editing a client proposal, and reset invalidate the affected access immediately. Entry can create a fresh run while the judging code remains valid.
- **Reopen client review:** use **Client review link** on the designer's current order. It reopens that revision even after approval/payment and does not create another invoice. Editing requires a fresh client review and explicit approval.
- **Lost browser state:** use privately saved designer access in Connect, or use the judging code to start a new run. Private access is stored in browser local/session storage and Figma `clientStorage`; avoid shared browser profiles. Clear site data or disconnect after testing on a shared device.
- **Interrupted invoice:** approval remains saved. The designer can choose **Prepare PayPal invoice** again. The backend reconciles and resumes the same invoice rather than generating another one.
- **Delayed webhook:** **Check payment** / **Refresh payment status** directly retrieves PayPal truth. Manual refresh is separate from signed webhook evidence; the verification notes record whether a real callback was received.
- **Wrong Figma file:** open the designated file and rerun the plugin. Frame attachment is disabled for another file. Comments and the brief always come from the configured file.
- **An older development build opens:** in Plugins & widgets, find the old Scope & Settle entry by its local manifest path and choose its menu → Remove. This removes the development registration, not its source files. Keep only the entry pointing to the freshly extracted ZIP, then rerun it. Registrations with the same plugin ID can otherwise launch the older build.
- **Figma access unavailable:** use **Open browser workspace** to exercise comments, assessment, terms, approval and payment. Native frame selection/export still requires Figma desktop and edit access.
- **AI allowance exhausted:** the app stops live requests and shows the error. Reset and new runs do not reset the allowance. **Prepare a manual proposal** is an explicitly labeled payment-testing path; it is not live AI evidence.

The prebuilt plugin calls only the displayed hosted origin. No provider keys, judging code or sandbox buyer password are included in the ZIP. Keep private credentials and role links out of public source and recordings.

For local setup use the repository README with Node 24, `pnpm install --frozen-lockfile`, your own explicit sandbox/provider configuration, then `pnpm build` and `pnpm start` in `app`. Build the plugin with the matching `PUBLIC_BASE_URL`. Restore the synthetic file using `docs/FIGMA-JUDGING-FILE.md`; a restored file requires configuring its actual file key before provisioning new judging access.
